**Status.** The loop is how I work. The two transcripts and the log fixture are invented for teaching. The script is Computed: you can run it. How well the loop works for you is not measured.

## Two roles

In this loop the assistant is the tech lead. You are the product manager of your own tools.

The tech lead builds, explains and recommends. The product manager decides what is worth building. You do not need to read the code to hold that role. You need to try the result and say what you want.

## One cycle

Each cycle has five steps. Repeat them until you say stop.

1. **Build.** The assistant builds one small slice, the smallest piece you can try.
2. **Tell.** The assistant says what it built in plain words, in a few lines.
3. **Try.** You use the slice in your own interface. The assistant watches the outcome in the system (a file, a log, a result), not only what you say.
4. **Ask.** The assistant asks for feedback. It leads with a recommendation and a named next step.
5. **Decide.** You accept, reject or steer. The assistant starts the next slice.

The assistant leads and tells you what to do next. You decide. A menu of equal options pushes the work back on you, so the assistant picks one and gives its reason.

## The assistant tells you what to do next

Recommending the next improvement needs evidence. One source is a log of what you did. If you do the same step by hand again and again, that step is a candidate for a tool.

The script below reads an actions log in the format of the [observability page](../../shelf/operations/observability/). It counts the steps that finished more than once. It ranks them by the total minutes, and it prints a recommendation for the top three.

The log may also carry a `minutes` field on a line, the time one run of the step took. The observability format does not have this field. Without it, a step counts as 1 minute. The script ignores `pre` lines, because a `pre` line is an attempt and not a finished step.

To run the example, use the command in the evidence line. To run its tests, run `python3 -I -m unittest discover -s examples/improvement-queue`. Eleven tests pass on 2026-10-26 with Python 3.13.1. They cover the ranking, the rare and cheap step, the empty log and the malformed line.

A malformed line stops the script. It does not skip the line, because a skipped line would change the ranking without telling you. Here is the real output for a log whose second line is broken. The script exits with code 1.

```text
error: line 2: not a valid log line (JSONDecodeError('Expecting property name enclosed in double quotes: line 1 column 2 (char 1)'))
```

Treat the recommendation as a suggestion. You decide. Before you build the tool, count the cost of building and keeping it against the minutes the log shows.

## What the assistant must not do

- It must not give a list of options with no recommendation.
- It must not report a slice as working without a check of the outcome in the system.
- It must not start the next slice before you have tried the last.
