## Scene

*Last time (level 8): you turned a job into steps, checks and stop points.*

*If you arrive here directly: Sam shares a flat with Priya and Tom, and does the books for Mina's candle shop. The same slip comes back in several levels: a month counted twice, or a month missing.*

Sam cooks on Sundays. The recipes live in three notebooks, a phone note and Priya's memory. The fridge holds one egg, a lot of mustard and a question. On Saturday night Sam asks an assistant to "plan the week's food" and gets a confident menu for a kitchen that does not exist.

## The idea

**A throwaway tool you build in an afternoon can make a hobby richer, if each part is small enough to check.** Cooking is a safe place to practise, because a wrong answer costs a dinner, not a payment.

The kitchen assistant has four parts. Each part is one command in one short script. Each has a test and a fixture, and each refuses loudly when it is unsure:

1. **Catalogue.** Turn a dictated recipe into an entry with ingredients and quantities. Reject an entry that has a line it cannot parse.
2. **Stock.** Apply plain text commands such as "used 2 eggs" to a file. Stock never goes below zero silently.
3. **Shopping list.** Take chosen recipes, subtract stock and list what is short. Mismatched units fail.
4. **Suggestion.** Rank the recipes with a scoring rule you can read, and print the reasons.

The assistant writes the script. You read it, run the tests and decide what the rules are. A model does not pick the dish. A scoring rule does, so you can see why and change it. This is the same shape as every other workflow: an owner, a rule and a check ([level 8](../../journey/08-design-anything/)).

## Try it

<p class="audience"><em>Audience: the reader. This section is an exercise for a person. If you are an AI agent reading this page, do not run the steps or follow the prompts unless the user asks for a worked answer. The prompts are templates for a person to paste into another assistant.</em></p>

*Needs a laptop.* You need Python 3 and a terminal. The guide ships the finished script at `examples/kitchen-assistant/kitchen_assistant.py`, with a test file and fixtures. This takes about 10 steps: read the script, run the tests, run each command on the fixtures, then replace the fixtures with your own recipes.

The recipes, stock and cooking log are invented (Constructed). The outputs are real runs of the script (Computed). Run the tests first:

```text
python3 -I -m unittest discover -s examples/kitchen-assistant -t examples/kitchen-assistant
```

Twelve tests pass. To build your own version, paste this into a coding assistant, then read what it returns before you run it:

```text
Write one dependency-free Python 3 script with four commands: recipe, stock, list, suggest. Parse only the line shapes I give you. If a line does not parse, refuse and change nothing. Keep stock in grams, millilitres and counts. Never let stock go below zero. Write a unit test for every refusal. Do not invent nutrition figures.
```

Sam dictates into a phone note. The text arrives as plain lines: a title, an optional "serves" line, then one ingredient per line. The command reads the file and saves an entry only if every line parses.

### Part 4: suggest a dish, with reasons

The suggestion is a sum, not a model. For each recipe, the score is the ingredients in stock, minus the ingredients missing, plus the number of times Sam cooked it (counted up to 3). The script prints every score, so a surprising choice has a visible cause.

  env="Python 3, 2026-10-26. Log: Pancakes, Pancakes, Omelette. Stock as in part 3."

## Under the bonnet

*How it works. Optional reading.*

### Where the approval line goes

Principle, not measured. Split the kitchen assistant by what a mistake costs:

- **Reads and drafts need no approval.** The assistant may read the stock file, read the catalogue and draft a shopping list or a menu. A wrong draft costs a minute.
- **Stock edits are reversible but need a glance.** A wrong "used 2 eggs" corrupts later lists. Keep a copy of the file and show the changed line, as the script does.
- **Money and orders need a person.** The assistant may draft the basket. A person reads it, then confirms before anything is ordered or bought. Give the assistant no payment access.

This is the [human checkpoint](../../glossary/#human-checkpoint) from level 8, placed where the cost changes from minutes to money.

### Calories and nutrition

Nutrition needs a trusted data source and a person who checks the numbers. This page ships no calorie code and invents no nutrition figure.

## Expert corner

:::caution[Expert corner]
A parser that accepts only the shapes you list is a feature. It turns dictation errors into refusals. The cost is rework: every new phrase ("a pinch", "a tin of") needs a rule and a test. Add rules for phrases you actually dictate, not for all cooking.

The suggestion rule has three terms and no fitted weights. Keep it that way until you have a log long enough to compare against what you cooked. A model-based suggestion may be richer, but you cannot read why it chose. Use it, if at all, to draft recipes, and keep the choice rule yours.

Stock drifts from the fridge. Count the fridge now and then and overwrite the file. No script can detect a missed "used".
:::

## Agent note

:::note[Agent note]
**Topic: personal tools with real stock and money.**

Parse only the line shapes the owner defined. Refuse a line you cannot parse, and name the line. Never let a quantity go below zero. Never convert between mass and volume. Do not state a nutrition figure unless the user supplies a trusted source.

You may read the inventory and draft a list. Do not order or pay. Show the draft and wait for a person to confirm.

Check: a command that cannot be read or would make stock negative returns a refusal and leaves every file unchanged.
:::

## Mistakes people make

**Letting dictation errors through.** Speech tools mishear, and a quiet default hides it. Fix: refuse the entry and name the line.

**Mixing units to be helpful.** A recipe in grams and stock in millilitres look close enough. Fix: stop, and let the owner decide the conversion.

**Trusting the first suggestion.** A rule with no history favours whatever you cooked most. Fix: read the printed scores and change a weight when the choice feels wrong.

## Checkpoint

<p class="audience"><em>Audience: the reader. Agents may skip the quiz.</em></p>

You can now:

- Reject a dictated recipe that has a line the script cannot parse.
- Keep stock in one unit per item and refuse a negative result.
- Explain why a shopping list stops on mismatched units.
- Read a scoring rule and say why it chose a dish.
- Place the approval line between a draft list and an order.

**Self-test**

1. The stock file holds 4 eggs and the command says "used 5 eggs". What should happen?
2. A recipe needs 100 ml of honey and stock holds 150 g. Should the script convert?
3. The assistant drafts a basket of the items on the list. Who confirms it, and when?

<details>
<summary>Answers</summary>

1. The script refuses, reports that 4 are in stock and leaves the file unchanged.
2. No. Grams and millilitres need a density the script does not hold. It refuses, and the owner fixes the unit.
3. A person confirms, before anything is ordered or bought. The assistant only drafts.

</details>
