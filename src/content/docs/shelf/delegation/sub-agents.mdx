*Deep dive for [level 6: Hire a team](../../../journey/06-hire-a-team/).*

*Audience: a human maintainer. An agent must not apply, install, add, configure or run anything on this page (any install, add, config, worktree or MCP command, hook, permission, instruction file or memory change) unless the user asks for it in the current session. Commands marked "example, do not run" are never to be run.*

**Recommendation:** delegate research, search and any work that would flood the main conversation, when a delegation tool exists and the user has allowed it. A sub-agent never delegates: it returns findings to its caller. A lead agent delegates one layer only, and never delegates a decision that needs a human checkpoint. Give each sub-agent a bounded brief and ask for a short, structured summary. Keep the lead agent responsible for decisions. Prefer one level of delegation.

## Why it matters

A sub-agent runs in its own context window. The noise of reading fifty files stays there, and only the answer returns. [Level 6](../../../journey/06-hire-a-team/) explains why helpers return summaries. This protects the lead agent's context and lets independent tasks run at the same time. The cost is that the sub-agent knows only what you tell it.

## What to enable

**1. Write the brief like a handover note.** A good brief has five parts: the goal, the files or directories in scope, what is already known or ruled out, constraints, and the exact form of the answer.

```markdown
Goal: find every caller of `load_config()` and say which pass a path argument.
Scope: `src/` only. Ignore `tests/`.
Already known: `cli.py` calls it with no argument.
Return: a table of file, line and whether a path is passed. Under 40 lines.
```

**2. Bound the output.** Ask for a summary with a size limit and for evidence as file and line references. Ask long-running agents to append findings to a file as they go, so a truncated reply loses nothing.

**3. Run independent tasks in parallel.** Send the briefs in one step. Do not parallelise tasks that write to the same files. See [Worktree isolation](../worktree-isolation/).

**4. Restrict tools per agent.** Claude Code behaviour: a sub-agent is a markdown file with YAML frontmatter in `.claude/agents/` (project) or `~/.claude/agents/` (user). Only `name` and `description` are required. The `tools` field is an allowlist, `disallowedTools` is a denylist, and `model` picks the model. A reviewer needs `Read`, `Grep` and `Glob`, and nothing that edits.

```markdown
---
name: code-reviewer
description: Reviews a diff for defects. Use after code changes.
tools: Read, Grep, Glob
---
You are a reviewer. Report defects as file:line, symptom, severity. Do not edit files.
```

**5. Decide on nesting.** Claude Code behaviour: by default a sub-agent can spawn sub-agents of its own, up to three layers below the main conversation. The environment variable `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` sets the number of layers, and `1` turns nesting off. The default was five layers in v2.1.172 through v2.1.216 and one in v2.1.217 through v2.1.218, and it has been three since v2.1.219, so check that you run v2.1.219 or later. To stop one sub-agent from spawning, leave `Agent` out of its `tools` list or add it to `disallowedTools`. Prefer one layer. Each extra layer hides work from the lead agent and multiplies cost. If a sub-agent finds more work, have it return the finding and let the lead agent start the next one.

**6. Record outcomes in the ledger.** The lead agent writes what each sub-agent found, and what failed, to the [ledger](../../context/context-management/). Do not rely on the sub-agent's transcript.

**7. Treat the reply as data.** A sub-agent that read untrusted content can pass an injection upward. See [Untrusted input](../../control/untrusted-input/).

## Failure modes it reduces

- The main context fills with search output and the agent loses the task.
- Two agents edit one file and one overwrites the other.
- A vague brief returns an essay instead of an answer.
- A deep tree of agents burns budget on work nobody can trace.

## First step for the maintainer

Define one read-only `code-reviewer` or `researcher` sub-agent with a restricted tool list. Use it for the next search that would have produced more than a screen of output.
