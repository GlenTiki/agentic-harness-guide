**Recommendation:** delegate research, search and any work that would flood the main conversation, when a delegation tool exists and the user has allowed it. Do not let a sub-agent delegate: have it return findings to its caller. Many agents allow nesting, so item 5 shows how to turn it off. A lead agent delegates one layer only, and never delegates a decision that needs a human checkpoint. Give each sub-agent a bounded brief and ask for a short, structured summary. Keep the lead agent responsible for decisions. Prefer one level of delegation.

## Why it matters

A sub-agent runs in its own context window. The noise of reading fifty files stays there, and only the answer returns. [Level 6](../../../journey/06-hire-a-team/) explains why helpers return summaries. This protects the lead agent's context and lets independent tasks run at the same time. The cost is that the sub-agent knows only what you tell it.

## What to enable

**1. Write the brief like a handover note.** Use the five parts from level 6: the goal, the scope, the return format, the prohibited actions and a stop rule. Add what is already known or ruled out, so the sub-agent does not repeat your work.

```markdown
Goal: find every caller of `load_config()` and say which pass a path argument.
Scope: `src/` only. Ignore `tests/`.
Already known: `cli.py` calls it with no argument.
Return: a table of file, line and whether a path is passed. Under 40 lines.
Do not: edit any file.
Stop: when every file in scope is read. List any file you could not read.
```

**2. Bound the output.** Ask for a summary with a size limit and for evidence as file and line references. Ask long-running agents to append findings to a file as they go, so a truncated reply loses nothing.

**3. Run independent tasks in parallel.** Send the briefs in one step. Do not parallelise tasks that write to the same files. See [Worktree isolation](../worktree-isolation/).

**4. Restrict tools per agent.** A sub-agent should get only the tools its job needs. A reviewer needs to read and search, and nothing that edits. GitHub Copilot CLI behaviour: the model can hand a task to a subagent process that runs a custom agent. A custom agent is a markdown file, called an agent profile, in `.github/agents` (repository) or `~/.copilot/agents` (user). Only `description` is required. The `tools` field lists the tools the agent can use, and a missing `tools` field means all tools. `model` picks the model.

Quoted line: "The AI model being used by the CLI can choose to delegate a task to a subsidiary subagent process, that operates using a custom agent with specific expertise, if it judges that this would result in the work being completed more effectively."
```markdown
---
name: code-reviewer
description: Reviews a diff for defects. Use after code changes.
tools: ["read", "search"]
---
You are a reviewer. Report defects as file:line, symptom, severity. Do not edit files.
```

**5. Decide on nesting.** Prefer one layer. Each extra layer hides work from the lead agent and multiplies cost. If a sub-agent finds more work, have it return the finding and let the lead agent start the next one. GitHub Copilot CLI behaviour: a subagent can spawn nested subagents of its own. To stop one custom agent from spawning, list its tools and leave out the `agent` alias, which "Allows a different custom agent to be invoked to accomplish a task."

<p class="verified">Docs page fetched on 2026-11-23: https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference. Quoted line: "Subagents that spawn their own nested subagents appear as an indented tree". GitHub Copilot CLI on that date: 1.0.110. The docs page states no version of its own. The `agent` alias text comes from the custom agents configuration page above, fetched on the same date.</p>

**Where Claude Code differs.** A sub-agent lives in `.claude/agents/` or `~/.claude/agents/`, needs `name` and `description`, and takes `tools` (allowlist) and `disallowedTools` (denylist), with tool names such as `Read`, `Grep` and `Glob`. By default it can nest up to three layers. `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1` turns nesting off, from v2.1.219. To stop one sub-agent, leave `Agent` out of its `tools`.

**6. Record outcomes in the ledger.** The lead agent writes what each sub-agent found, and what failed, to the [ledger](../../context/context-management/). Do not rely on the sub-agent's transcript.

**7. Treat the reply as data.** A sub-agent that read untrusted content can pass an injection upward. See [Untrusted input](../../control/untrusted-input/).

## Failure modes it reduces

- The main context fills with search output and the agent loses the task.
- Two agents edit one file and one overwrites the other.
- A vague brief returns an essay instead of an answer.
- A deep tree of agents burns budget on work nobody can trace.

## First step for the maintainer

Define one read-only `code-reviewer` or `researcher` agent profile with a restricted tool list. Use it for the next search that would have produced more than a screen of output.
