**Recommendation:** cite a heading anchor in prose and a line number only for code. Check every line citation at commit. Fail the commit on an unresolved citation in a live document. Mark a dated snapshot with a first-line comment so the check skips it.

## Why it matters

A citation such as `src/pricing.py:3` is true on the day you write it. The next edit that adds a line above it makes it point at the wrong code, and nothing warns the reader. An agent that follows the citation reads the wrong function and reports it with confidence. The page on [link and reference checks](../../../setup/link-and-reference-checks/) describes the same drift for links. This page adds the line-number case.

## What to enable

**1. Prefer an anchor.** In Markdown, link to a heading, such as `spec.md#acceptance-criteria`. A heading survives edits that add lines. Use a line number for code, where no heading exists.

**2. Name the symbol next to the number.** Write the citation with the thing it points at, so a checker can tell when the line no longer holds it. The checker in this guide reads a citation in this form: the path and line in backticks, then `defines`, then the symbol in backticks.

**3. Check at commit.** A check that runs only when someone remembers will not run.

**4. Hard fail in live documents.** A live document is one a reader or agent acts on today: a spec, a README, an instruction file. An unresolved citation there stops the commit. A warning that people can ignore becomes noise.

**5. Mark snapshots.** A dated report or journal entry records what was true then. Its citations are meant to age. Put `<!-- snapshot: YYYY-MM-DD -->` as the first line and the checker skips the file. The marker must be the first line, so it cannot be added quietly lower down.

## Limits of this checker

It reads only citations in backticks that carry the `defines`, `calls` or `sets` form for the symbol check. It matches the symbol name as text on the cited line, so a comment that mentions the name satisfies it. It does not parse code. A language-aware tool would be stricter, and costs more to maintain.
