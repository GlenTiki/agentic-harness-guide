**Status.** Built in the case study. Every command and output below was run on 2026-10-25 from a fresh unzip of `ch04-reference-walker.zip`, with Python 3.13.1.

**Time.** Running the steps takes about 10 minutes (6 steps, [counted like this](../#how-to-use-a-chapter)). Reading the code takes longer: about 20 to 30 minutes more.

## The weak spot

Deep references rot. A claim cites a document that cites another, and a link check cannot tell whether the text still supports the claim.

## Goal

Follow references from a root document for a bounded number of hops and report where a cited text no longer supports the claim.

## What is in the kit

- `refwalk.py`. The function `walk` is the whole algorithm: a queue, a visited set and a depth for each document.
- `example/refwalk.json`, a config that sets `max_depth` to 2, `max_path_length` to 80 and `max_files` to 50.
- Cycle detection. A document that is an ancestor on the current chain is not followed again.
- A judge plug-in point. The built-in `lexical` judge counts shared words. You can pass your own program with `--judge-command`.

## Get the kit

Download [ch04-reference-walker.zip](/agentic-harness-guide/downloads/ch04-reference-walker.zip). Then run these commands in the folder that holds it:

```text
shasum -a 256 ch04-reference-walker.zip
unzip ch04-reference-walker.zip -d kit
cd kit/ch04-reference-walker
```

The hash must be `06015117901a179dd81175588985c7283fb58a755ffc3881058c17094eff2595`. If it differs, stop. On Linux use `sha256sum`. This folder is the kit root. Run every command from it. [How the kits work](../#how-to-use-a-chapter).

## Steps

1. Compare the checksum, then unzip (see above).
2. Read `refwalk.py` and `example/refwalk.json`.
3. Walk the example with the lexical judge: `python3 -I refwalk.py example/root.md --config example/refwalk.json --judge lexical`.
4. Walk again with `max_depth` 1, then with `max_depth` 5. The kit writes each config under `scratch/`. The second and third Examples show the commands.
5. Optional idea: plug in your own judge with `--judge-command`. The program reads `{"claim": ..., "source": ...}` on stdin and prints `{"supported": true, "reason": "..."}`. I did not run a custom judge for this page.
6. Run the validator: `python3 -I validate.py`. It prints `validate: PASS`.
7. Prove the check can fail: `python3 -I validate.py --bad`. The exit code is 1.

## What is not tested

No language model is involved in this chapter. The built-in judge is a word-overlap counter. It is a stand-in so that the tests are repeatable. A model judge is the intended use, and nothing here tests one. The walker follows only local Markdown links and calls no network service.
