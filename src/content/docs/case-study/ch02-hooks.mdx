## The weak spot

The [agent](../../glossary/#agent) forgets the rules. A rule in an instruction file is advice. A hook runs when its event fires, and the agent cannot decide to skip it. It can still be misconfigured or fail open.

## Goal

Run five hooks through one dispatcher and prove each one blocks, allows or fails closed as designed.

## What is in the kit

- `dispatch.py`, a hook dispatcher. It follows the exit-code contract: 0 allows, 2 blocks, any other non-zero code is a non-blocking error. Bad input fails closed.
- Five example hooks in `hooks/`: `block_destructive_bash.py`, `protect_files.py`, `inject_rules.py`, `log_tool_use.py` and `stop_if_open_checklist.py`.
- `hooks.json`, which maps each event and tool name to a script.
- `matrix.json`, a test matrix of 19 cases: allow, deny and malformed input.
- `claude-settings.example.json`, a settings snippet for Claude Code.

## Get the kit

Download [ch02-hooks.zip](/agentic-harness-guide/downloads/ch02-hooks.zip). Then run these commands in the folder that holds it:

```text
shasum -a 256 ch02-hooks.zip
unzip ch02-hooks.zip -d kit
cd kit/ch02-hooks
```

The hash must be `f9af645321bd40c9010d56228f6c011fb47bbc3c3e97aa0e9e9f987088f72ce2`. If it differs, stop. On Linux use `sha256sum`. This folder is the kit root. Run every command from it. [How the kits work](../#how-to-use-a-chapter).

## Steps

1. Compare the checksum, then unzip (see above).
2. Read `dispatch.py` and the five scripts in `hooks/`.
3. Read `hooks.json`. It maps each event and tool name to a script.
4. Run the matrix: `python3 -I validate.py`. It also installs the kit into a scratch project and follows the commands in `claude-settings.example.json`.
5. Pipe one event into the dispatcher by hand and read the exit code. The second Example shows the command.
6. Point the dispatcher at a config that does not exist. It still blocks.
7. Prove the check can fail: `python3 -I validate.py --bad`. The exit code is 1.

To use the hooks in Claude Code, copy `dispatch.py`, `hooks.json` and the `hooks/` folder into `.claude/harness-hooks/` in your project. Then merge `claude-settings.example.json` into `.claude/settings.json`. The commands in it name `${CLAUDE_PROJECT_DIR}/.claude/harness-hooks/dispatch.py`. If you put the files elsewhere, change that path. A path that does not exist makes the hook fail on every call, and the validator checks the sample path for that reason.

## What is not tested

The behaviour inside a live Claude Code session is not tested. I ran nothing inside Claude Code for this chapter. The settings snippet follows the documented shape: an event name, a list of groups with an optional matcher, and a list of hooks with `type` and `command`. The tests check that shape and that the path resolves. The claims about exit codes come from the Claude Code hooks documentation, which the setup page quotes. The tests run against this dispatcher, not against Claude Code.
