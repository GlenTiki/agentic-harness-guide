*Audience: a reader who wants to build along. An agent must not run any command on this page unless the user asks for it in the current session.*

**Status.** Built in the case study. Every command and output below was run on 2026-10-25 from a fresh unzip of `ch05-memory.zip`, with Python 3.13.1.

**Time.** Running the steps takes about 10 minutes (7 steps, [counted like this](../#how-to-use-a-chapter)). Reading the code takes longer: about 20 to 30 minutes more.

## The weak spot

The [agent](../../glossary/#agent) forgets you. Loading every note wastes [tokens](../../glossary/#token). Loading none repeats the problem.

## Goal

Pick a bounded, repeatable set of notes for a prompt and record which notes were used.

## What is in the kit

- Eight memory files in `example/memories/`. Each is a plain text file. The front matter holds a name, a type and an `updated` time in UTC to the second.
- `bm25.py`, about 40 lines, written from the published formula.
- `memory.py`, a loader. It scores every memory against the prompt, picks the best ones that fit a token budget (400 by default) and writes one line to a recall log.
- `validate.py`, which checks every memory file and six golden prompts in `example/golden.json`.

## Get the kit

Download [ch05-memory.zip](/agentic-harness-guide/downloads/ch05-memory.zip). Then run these commands in the folder that holds it:

```text
shasum -a 256 ch05-memory.zip
unzip ch05-memory.zip -d kit
cd kit/ch05-memory
```

The hash must be `502f98061b46dd5811bc10fa61108ecb21573b9317d976fe72e329c6727b6bc4`. If it differs, stop. On Linux use `sha256sum`. This folder is the kit root. Run every command from it. [How the kits work](../#how-to-use-a-chapter).

## Steps

1. Compare the checksum, then unzip (see above).
2. Read the eight files in `example/memories/`. You can edit each one by hand.
3. Read `bm25.py`.
4. Recall for a prompt. The log goes to `scratch/`: `mkdir -p scratch`, then `python3 -I memory.py "Write the commit message for this change" --dir example/memories --log scratch/recall.jsonl`.
5. Read the log line it wrote.
6. Run the validator: `python3 -I validate.py`. It prints `validate: PASS`.
7. Prove the check can fail: `python3 -I validate.py --bad`. The exit code is 1.

## What is not tested

BM25 matches words, not meaning. A prompt about "tidy history" does not find a memory about "small commits". The token count is an estimate of four characters per token. This is the memory system of the case study, not of any real assistant. Nothing here was run inside Claude Code, Codex or Gemini. The "timestamp" example is one extra command that I ran for this page. It is not a step in the kit.
