**Status.** Built in the case study. Every command and output below was run on 2026-10-25 from a fresh unzip of `ch03-link-resolver.zip`, with Python 3.13.1.

**Time.** Running the steps takes about 10 minutes (6 steps, [counted like this](../#how-to-use-a-chapter)). Reading the code takes longer: about 20 to 30 minutes more.

## The weak spot

Documents drift from reality. A pointer to a renamed file or heading stays in the text and the document lies.

## Goal

Catch every broken relative link, file path and heading anchor at commit time.

## What is in the kit

- `linkcheck.py`, a Markdown link linter. It checks every relative path, file link, heading anchor and image path.
- `example/`, a small folder of good files with one external link that the linter does not fetch.
- `validate.py`, which checks `example/` and the Markdown files at the top of the kit (`README.md`, `CHAPTER.md` and `SPEC.md`).
- `fixtures/bad/broken.md`, a failing fixture.

## Get the kit

Download [ch03-link-resolver.zip](/agentic-harness-guide/downloads/ch03-link-resolver.zip). Then run these commands in the folder that holds it:

```text
shasum -a 256 ch03-link-resolver.zip
unzip ch03-link-resolver.zip -d kit
cd kit/ch03-link-resolver
```

The hash must be `4e9f6f4fdab1f59cc0e27d0ce0e5b2dc656d5476a57a29be6b171698e9dd2c4d`. If it differs, stop. On Linux use `sha256sum`. This folder is the kit root. Run every command from it. [How the kits work](../#how-to-use-a-chapter).

## Steps

1. Compare the checksum, then unzip (see above).
2. Read `linkcheck.py`.
3. Run it on the good example: `python3 -I linkcheck.py example`.
4. Run the validator: `python3 -I validate.py`. It prints `validate: PASS`.
5. Rename a heading in a copy and check the copy. The second Example shows the commands.
6. Prove the check can fail: `python3 -I validate.py --bad`. The exit code is 1.

## What is not tested

The linter does not fetch links to other sites. The rules that turn a heading into an anchor follow my reading of the GitHub rules. They were not compared with github.com. Markdownlint rule MD051 checks anchors inside one document only, and this linter also covers links to other files. A pre-commit entry for the linter is not built.
