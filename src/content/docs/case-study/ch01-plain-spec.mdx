*Audience: a reader who wants to build along. An agent must not run any command on this page unless the user asks for it in the current session.*

**Status.** Built in the case study. Every command and output below was run on 2026-10-25 from a fresh unzip of `ch01-plain-spec.zip`, with Python 3.13.1.

**Time.** Running the steps takes about 10 minutes (6 steps, [counted like this](../#how-to-use-a-chapter)). Reading the code takes longer: about 20 to 30 minutes more.

## The weak spot

Vague requests. A spec that can be read two ways will be built one way, and it may not be yours.

## Goal

Have specs in simple English that a rule-based linter can check, and know exactly what that linter cannot check.

## What is in the kit

- `example/TEMPLATE.md` and a worked example, `example/notes-add.md`.
- `plainlint.py`, a linter with four rules: sentence length (25 words in a description, 20 in a numbered step), passive voice, a list of banned vague words, and a readability grade (Flesch-Kincaid, limit 9).
- `validate.py`, which lints everything in `example/` and `SPEC.md`.
- Optional rules in the Vale format, in `vale/`. The tests do not need Vale.

## Get the kit

Download [ch01-plain-spec.zip](/agentic-harness-guide/downloads/ch01-plain-spec.zip). Then run these commands in the folder that holds it:

```text
shasum -a 256 ch01-plain-spec.zip
unzip ch01-plain-spec.zip -d kit
cd kit/ch01-plain-spec
```

The hash must be `37ebb74ea24195721c63fc28ed6dafc1119f1feecda1b591127824bd0c4fca62`. If it differs, stop. On Linux use `sha256sum`. This folder is the kit root. Run every command from it. [How the kits work](../#how-to-use-a-chapter).

## Steps

1. Compare the checksum, then unzip (see above).
2. Read `example/TEMPLATE.md` and the worked example `example/notes-add.md`.
3. Lint one file: `python3 -I plainlint.py example/notes-add.md`.
4. Run the validator: `python3 -I validate.py`. It prints `validate: PASS`.
5. Run the unit tests: `python3 -I -m unittest discover -s tests -t .`. The last line is `OK`.
6. Prove the check can fail: `python3 -I validate.py --bad`. The exit code is 1.

## What is not tested

The linter cannot check the licensed Simplified Technical English dictionary. It cannot check word sense or meaning. The passive-voice rule is a heuristic, and the test `test_known_false_positive_is_documented` records a sentence it flags wrongly. Vale is optional and the kit does not install it: `vale --config vale/.vale.ini example/notes-add.md`. The Vale rules mirror three of the rules (vague words, sentence length and passive voice) and do not compute the readability grade. I did not run Vale for this page. On 2026-10-24 I ran Vale 3.22.0 on the sample spec and on the failing fixture. The sample spec had 0 findings. The failing fixture had 5 errors and 5 warnings.
