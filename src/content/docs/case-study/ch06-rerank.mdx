## The weak spot

Keyword search misses the point. Notes with the right meaning and different words rank too low.

## Goal

Decide with numbers from your own machine whether a re-ranker is worth its cost.

## What is in the kit

- `rerank.py`. The function `rerank_ranker` takes the top 20 BM25 candidates and sorts them again with a scorer.
- Two scorers. A lexical scorer needs no package and is deterministic. An optional cross-encoder scorer uses `sentence-transformers` and the model `cross-encoder/ms-marco-MiniLM-L6-v2`.
- `evalset/`: 44 memories and 34 queries that one person labelled by hand.
- `evaluate.py`, which prints precision@3, hit@3 and MRR for each system, and with `--latency` times the cross-encoder.
- `results.json`, a regression guard for the two systems that need no package.

## Get the kit

Download [ch06-rerank.zip](/agentic-harness-guide/downloads/ch06-rerank.zip). Then run these commands in the folder that holds it:

```text
shasum -a 256 ch06-rerank.zip
unzip ch06-rerank.zip -d kit
cd kit/ch06-rerank
```

The hash must be `7cb9a08ab0642a246708c57493eaafc1ae76e0ab6cf99aa73b85e333d80f51cf`. If it differs, stop. On Linux use `sha256sum`. This folder is the kit root. Run every command from it. [How the kits work](../#how-to-use-a-chapter).

## Steps

1. Compare the checksum, then unzip (see above).
2. Read `rerank.py`.
3. Run the validator: `python3 -I validate.py`. It prints `validate: PASS`. Without `sentence-transformers` the unit tests report `OK (skipped=1)`.
4. Run the evaluation without extra packages: `python3 -I evaluate.py`.
5. Optional: try the real cross-encoder in a throwaway environment under `scratch/`. The kit lists the three commands. They need `uv` and a network. The stored run of the cross-encoder is in [examples/retrieval-eval/outputs/cross-encoder.txt](https://github.com/GlenTiki/agentic-harness-guide/blob/main/examples/retrieval-eval/outputs/cross-encoder.txt).
6. Prove the check can fail: `python3 -I validate.py --bad`. The exit code is 1.

### Measured results

The set has 44 memories and 34 queries. Precision@3 is low for every system because most queries have one correct memory, so a single-answer query scores at most 0.333 (1 of 3). Two queries have two correct memories, so the best possible mean for the whole set is 0.353 ((32 + 2 x 2) / (34 x 3)).

| system | precision@3 | hit@3 | MRR |
| --- | --- | --- | --- |
| bm25 | 0.265 | 0.794 | 0.643 |
| lexical rerank | 0.235 | 0.706 | 0.670 |
| cross-encoder rerank | 0.275 | 0.794 | 0.803 |

The first two rows are the output of the first Example above, and `results.json` guards them. The cross-encoder row has a stored output (below), run in a throwaway environment with sentence-transformers 6.2.0 and the model `cross-encoder/ms-marco-MiniLM-L6-v2`. The kit does not guard it, because the package is optional.

1. The cross-encoder put the first correct memory higher (MRR 0.643 to 0.803) and left hit@3 at 0.794.
2. The lexical fallback improved MRR a little and lowered hit@3 and precision.
3. With 34 queries, one query moves hit@3 by 0.029. Treat small differences as noise.

**Latency.** An Apple silicon laptop under load, CPU only, torch 2.14.1 with 4 threads. The two stored runs (5 and 10 repeats) gave medians of 0.0295 and 0.0233 seconds and maxima of 0.0834 and 0.0823 seconds to re-rank 20 candidates for one prompt. Loading the model took 7.37 and 6.29 seconds. This is a rough size on one machine, not a benchmark ([latency.txt](https://github.com/GlenTiki/agentic-harness-guide/blob/main/examples/retrieval-eval/outputs/latency.txt)).

**Determinism.** The lexical scorer gave identical output over 25 repeated runs in the unit tests. The cross-encoder gave identical scores over 10 repeated runs of all 34 prompts ([latency.txt](https://github.com/GlenTiki/agentic-harness-guide/blob/main/examples/retrieval-eval/outputs/latency.txt)). Other hardware or thread counts can change the last decimals, so the pipeline rounds scores to five decimals before it sorts.

## What is not tested

The cross-encoder row is not guarded by `results.json`. One small hand-written evaluation set is weak evidence. The latency figures come from one loaded machine on one day. The tests do not cover the cross-encoder unless you install the package.
