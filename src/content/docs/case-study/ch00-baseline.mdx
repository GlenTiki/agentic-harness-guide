*Audience: a reader who wants to build along. An agent must not run any command on this page unless the user asks for it in the current session.*

**Status.** Built in the case study. Every command and output below was run on 2026-10-25 from a fresh unzip of `ch00-baseline.zip`, with Python 3.13.1.

**Time.** Running the steps takes about 10 minutes (6 steps, [counted like this](../#how-to-use-a-chapter)). Reading the code takes longer: about 20 to 30 minutes more.

## The weak spot

Nothing is checked. Without a baseline you cannot tell whether a later check works or only looks like it works.

## Goal

Get a small sample project, a single command that checks it, and proof that the command can report a failure.

## What is in the kit

- `notes.py`, a plain-text notes tool. It adds, lists and searches notes. One note is one line: a UTC time stamp to the second, a tab, then the text.
- `validate.py`, which runs the unit tests and prints one verdict.
- `fixtures/bad`, a copy of the tool that drops the seconds from the time stamp. Its only job is to prove the check can go red.

## Get the kit

Download [ch00-baseline.zip](/agentic-harness-guide/downloads/ch00-baseline.zip). Then run these commands in the folder that holds it:

```text
shasum -a 256 ch00-baseline.zip
unzip ch00-baseline.zip -d kit
cd kit/ch00-baseline
```

The hash must be `c7135ce6e57d41e131c4fffb697d22b7d9d569e76ddf56177dfde2cef16e8edb`. If it differs, stop. On Linux use `sha256sum`. This folder is the kit root. Run every command from it. [How the kits work](../#how-to-use-a-chapter).

## Steps

1. Compare the checksum, then unzip (see above).
2. Read `notes.py`. It has no dependencies.
3. Run the tests: `python3 -I -m unittest discover -s tests -t .`.
4. Run the validator: `python3 -I validate.py`.
5. Add a note and list it. The first command makes the `scratch` folder: `mkdir -p scratch`, then `python3 -I notes.py --file scratch/notes.txt add "buy milk"`, then `python3 -I notes.py --file scratch/notes.txt list`.
6. Prove the check can fail: `python3 -I validate.py --bad`. The exit code is 1.

## What is not tested

Nothing here depends on a tool version. The chapter proves that the check can go red on one defect, a time stamp without seconds. It does not prove the check finds every defect. A path that cannot be used gives one line and exit code 2, not a traceback. The kit's `CHAPTER.md` shows that command.
