**Time.** Running the steps takes about 10 minutes (8 steps, [counted like this](../#how-to-use-a-chapter)). Reading the code takes longer: about 20 to 30 minutes more.

## The weak spot

One [agent](../../glossary/#agent) does everything, or helpers get a brief with no rules. A helper without the rules can break them.

## Goal

Write briefs from templates and catch any helper brief that is missing the shared rules block.

## What is in the kit

- `templates/orchestrator-brief.md`: outcomes in plain English, expected behaviour, acceptance checks and a next step. A worked example is in `example/briefs/orchestrator-notes-search.md`.
- `templates/subagent-brief.md` and `shared-rules.md`, a block of six rules.
- `briefs.py`, which renders a helper brief with the shared rules block and checks every brief in a folder.
- `settings-for-subagents.example.json` and `hooks/subagent_must_quote_check.py`. The hook blocks a helper's first attempt to finish unless its last message contains the text `ALL CHECKS PASSED`. It blocks once: when the harness sets `stop_hook_active`, the hook exits 0 so that it cannot loop. It checks the text only. It does not run the check, and a helper can repeat the text without running anything.
- `agents/reviewer.example.md`, an example agent definition.

## Get the kit

Download [ch07-orchestrator.zip](/agentic-harness-guide/downloads/ch07-orchestrator.zip). Then run these commands in the folder that holds it:

```text
shasum -a 256 ch07-orchestrator.zip
unzip ch07-orchestrator.zip -d kit
cd kit/ch07-orchestrator
```

The hash must be `6af24dfca0a9c7392c5a932064cf3b0e65e5f9a5f3cedd43bdae29a954a93d99`. If it differs, stop. On Linux use `sha256sum`. This folder is the kit root. Run every command from it. [How the kits work](../#how-to-use-a-chapter).

## Steps

1. Compare the checksum, then unzip (see above).
2. Read `templates/orchestrator-brief.md` and the worked example `example/briefs/orchestrator-notes-search.md`. This is what the product manager writes.
3. Read `shared-rules.md`.
4. Render a helper brief. The first Example below shows the command.
5. Check the example briefs: `python3 -I briefs.py example/briefs`.
6. Change one rule in a copy of an example brief and check again. The check fails.
7. Read `settings-for-subagents.example.json` and `hooks/subagent_must_quote_check.py`. To use them, copy the `hooks/` folder to `.claude/harness-subagent/hooks/` in your project and merge the settings. The validator installs the kit that way in a scratch project and follows the command in the settings.
8. Prove the check can fail: `python3 -I validate.py --bad`. The exit code is 1.

## What is not tested

The tests check the brief format, the extra hook and the shape of the config files. They do not run Claude Code. The shared rules block makes sure the rules are present in the brief. It cannot make a helper obey them. Enforcement comes from the hooks in chapter 2. What native Claude Code helpers inherit comes from the Claude Code documentation, which the setup page quotes with its fetch date. A helper that you start from a plain command-line program inherits none of it unless you pass the rules in.
