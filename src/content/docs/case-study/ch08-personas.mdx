**Status.** Design only, with a small working scaffold built in the case study. Every command and output below was run on 2026-10-25 from a fresh unzip of `ch08-personas.zip`, with Python 3.13.1.

**Time.** Running the steps takes about 10 minutes (8 steps, [counted like this](../#how-to-use-a-chapter)). Reading the code takes longer: about 20 to 30 minutes more.

## The weak spot

One viewpoint. A single reviewer sees only the angle it built from.

## Goal

Scaffold personas with a checklist and a memory file each, and validate the scaffold. Learn what the scaffold does not prove.

## What is in the kit

- Five persona files in `example/personas/`: architect, builder, tester, reviewer and releaser. Each has a role, a phase, a checklist of at least three items and a voice.
- One memory file for each persona in `example/personas/memory/`. Each line is a time, a hash and a note. The hash chains to the line before, so an edit to an old line shows.
- `personas.py` with three commands: `check`, `context` and `record`. `record` appends one line and refuses to append to a broken chain.
- `validate.py` and six failing folders in `fixtures/bad/`.

## Get the kit

Download [ch08-personas.zip](/agentic-harness-guide/downloads/ch08-personas.zip). Then run these commands in the folder that holds it:

```text
shasum -a 256 ch08-personas.zip
unzip ch08-personas.zip -d kit
cd kit/ch08-personas
```

The hash must be `184f902c450a037b8f6ac124a0cd6d087d24e58705e949f1cf7d5383d76d169c`. If it differs, stop. On Linux use `sha256sum`. This folder is the kit root. Run every command from it. [How the kits work](../#how-to-use-a-chapter).

## Steps

1. Compare the checksum, then unzip (see above).
2. Read the five files in `example/personas/`. Each has a role, a phase and a checklist.
3. Read one memory file in `example/personas/memory/`. Each line is a time, a hash and a note.
4. Check the folder: `python3 -I personas.py check`. It prints `personas: OK`.
5. Print what the tester would load: `python3 -I personas.py context tester`.
6. Copy the personas into `scratch/`, record a new interaction, and check the copy. Then edit an old note in the copy and check again. The second Example below shows the commands.
7. Run the validator: `python3 -I validate.py`. It prints `validate: PASS`.
8. Prove the check can fail: `python3 -I validate.py --bad`. The exit code is 1.

## What is not tested

This chapter is Design only, with a small working scaffold. The tests verify the file format, the chain check, the refusal to append to a broken memory, the context function and the six folder defects. They do not verify that personas catch more defects, that persona memory improves later work, or how a team lead should choose which persona runs. There is no evidence in this case study that personas help. The chain detects partial edits. It does not stop a full rewrite of a file. In my own setup, roles do not keep memories of their own.
