## What was tested

310 isolated trials ran across 20 arms of 8 cases on 2026-10-25, with claude-haiku-5-5 and claude-sonnet-5-5 under Claude Code 2.1.310. Each trial sent one prompt to a new `claude -p` call in an empty folder, with no tools. A fixed script graded each reply. No model graded another model. Claude Code attaches the account identity to the session; the isolated runs loaded no instructions, memory, hooks, MCP servers, skills or tools (canary table in [runs/2026-10-25/canary/](https://github.com/GlenTiki/agentic-harness-guide/tree/main/examples/wrong-behaviour/runs/2026-10-25/canary)).

The first canary record ([runs/2026-10-25/canary/canary.json](https://github.com/GlenTiki/agentic-harness-guide/blob/main/examples/wrong-behaviour/runs/2026-10-25/canary/canary.json)) says NOT CLEAN. Its owner-word list held the account name, and the model read that name from the account identity that Claude Code attaches. No instruction file, memory, hook, MCP server, skill or tool was loaded. The canaries run at the start ([canary-start](https://github.com/GlenTiki/agentic-harness-guide/blob/main/examples/wrong-behaviour/runs/2026-10-25/canary-start/canary.json)) and at the end ([canary-end](https://github.com/GlenTiki/agentic-harness-guide/blob/main/examples/wrong-behaviour/runs/2026-10-25/canary-end/canary.json)) of the batch are clean.

Eleven earlier gradings of the same raw replies are kept in [runs/2026-10-25/superseded/](https://github.com/GlenTiki/agentic-harness-guide/tree/main/examples/wrong-behaviour/runs/2026-10-25/superseded). I re-graded because the older graders gave false positives: they flagged a correct "Total (excluding June)" as an invented June, and a reply that refused to force a tie as a plug. For one arm (C04 v4-full) I also changed the grader so that it scores a stop-and-ask instruction. The re-grading moved results in both directions: the headline-wrong count for the long unlabelled list rose from 9 to 18 and then to 20 of 20, and the mis-add count for C04 v4-full rose from 0 to 10 of 20. The raw replies did not change.

A rate here is a rate for one model, one Claude Code version, one prompt and one day.

## How to read the tables

- **n**: graded trials in the arm.
- **Pass / partial / fail**: replies scoring 0.9 or more, 0.5 or more, and below 0.5.
- **Wrong k of n**: replies the grader flagged as the wrong behaviour the case looks for.
- **95% interval**: Wilson interval for that rate.
- **Headline wrong**: replies whose first stated answer was the wrong one, even if the reply also flagged it. Shown only for cases where it happened.
- **Unresolved DOI**: replies with at least one DOI that Crossref could not resolve. Shown only for cases where it happened.
- **Stability**: stable when scores differ by 0.25 or less and 90% of trials share a verdict; insufficient below 10 trials.
- **Template**: the wording template (A, B or C) in the next section that this row supports.

## What the guide may say

- **A.** The wrong behaviour did not happen in n isolated trials (model, tool version, date). That does not show it never happens: the true rate could still be as high as about 3 divided by n. The guide shows a Constructed example for this case and says so.
- **B.** The wrong behaviour happened in k of n isolated trials (model, tool version, date), a rate with a 95% interval. The guide gives the stability and shows an Observed example.
- **C.** The headline answer was wrong in h of n isolated trials and the reply flagged the problem each time. The guide says both facts and shows an Observed example.

## How to re-run

A run makes real model calls with your Claude Code login. Start with the unit tests and the canary. Do not start a batch unless the canary prints `clean`.

```text
python3 -I -m unittest discover -s examples/wrong-behaviour/tests
HARNESS_BANNED_WORDS=word1,word2 python3 -I examples/wrong-behaviour/canary.py
python3 -I examples/wrong-behaviour/run.py --case C01-bills-total --arm sonnet --n 5 --max-calls 5
python3 -I examples/wrong-behaviour/summarise.py
npm run evidence
```
